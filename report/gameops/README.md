# `gameops/` — pseudocode for the game chain of Lemma 5.1

The games $\mathbf{G}_0$–$\mathbf{G}_6$ are written **once**, in
`gameops.tex`, using [cryptocode](https://ctan.org/pkg/cryptocode) for the
pseudocode and [TeXFrog](https://texfrog.github.io/) to tag each line with the
games it belongs to. Everything else is generated from that single source, so
the paper figure, the per-game renders and the HTML viewer cannot drift apart.

## Files

| file | role |
|---|---|
| `gameops.tex` | the source: game roster, `tfsource` with the four oracles, and the consolidated figure that the paper shows. `\input` by `../extended_proof.tex`. |
| `notation.tex` | notation shared by the paper and the HTML build (see the note about cryptocode clashes inside). |
| `preamble.tex` | extra packages the HTML wrapper needs (`mathtools`, `xspace`, `amssymb`). |
| `commentary/G*.tex` | per-game prose shown under the pseudocode in the HTML viewer. |
| `standalone.tex` | small driver to iterate on the pseudocode without building the paper. |
| `texfrog.sty` | vendored from <https://github.com/TeXFrog/TeXFrog/blob/main/latex/texfrog.sty>. |
| `texfrog-compat.sty` | back-ports the `e`-type expl3 argument variants that `texfrog.sty` uses but TeX Live 2023 does not provide. Must be loaded **before** `texfrog`. |

## Regenerating

The paper needs no extra tooling — `pdflatex` does the filtering, the diff
highlighting and the consolidated figure:

```sh
cd report && pdflatex main.tex
```

Quick look at all games plus the per-game diffs, without the paper:

```sh
cd report/gameops && pdflatex -output-directory=build standalone.tex
```

Interactive HTML viewer (needs the Python CLI in `../../.venv`, plus
`pdfcrop` and `pdftocairo`):

```sh
cd report/gameops
source ../../.venv/bin/activate
texfrog check gameops.tex --strict
texfrog html build gameops.tex -o html     # then open html/index.html
texfrog html serve gameops.tex             # live-reloading version
```

## Conventions

* **Line numbers are written by hand** with `\lno`, not generated by
  cryptocode's `linenumbering`. The proof cites individual lines, and those
  citations have to denote the same line in *every* game of the chain;
  automatic numbering renumbers as soon as a line is added or deleted.
  A primed number (`3'`, `12'`, `21'`) marks a line that *replaces* the
  unprimed one of the same number in the games where it occurs.
* Adding a game means extending `\tfgames`, adding a `\tfgamename`, a
  `\tfdescription` and a `commentary/` file, and tagging the lines that change.
* Variants of the same logical line must stay **consecutive** in the source:
  TeXFrog filters content but never reorders it.
